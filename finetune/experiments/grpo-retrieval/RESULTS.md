## 结论

**在这个任务上，GRPO 没有带来提升，原因是组内样本的好坏没有可泛化的规律可学。** 两条独立证据指向同一个结论：

1. **可学性门槛不通过**：在没见过的 query 上，1.7B 打分模型判断两个扩展谁更好的准确率是 0.464，和随机相当；用它从 8 个样本里挑扩展，比 greedy 低 0.8pp。
2. **GRPO 短跑结果持平**：300 步后，在 3 个评测集上比 SFT 低 0.16pp，95% 置信区间 [−0.55, +0.23]，没过预先锁定的 +1pp 判据。训练奖励全程没有上升趋势。

门槛在训练前给出的预测，被训练结果验证了。

## 1. 问题和设置

- **任务**：Qwen3-1.7B 查询扩展模型（v2-VH SFT），输出 `hyde:` + `vec:` 行，送进 qmd 混合检索。
- **奖励**：用真实检索打分。格式错误记 −1；合格时记 ΔM − 长度惩罚。ΔM 是扩展后检索的 M 减去不扩展的 M，M = 0.7·nDCG@10 + 0.3·R@30。检索走 path A（不 rerank，RRF + rank fusion），奖励服务在 4090 上验收过，和离线标准答案逐位一致。
- **要回答的问题**：同一条 query 的 8 个采样之间检索分数有高有低。GRPO 能不能让模型学会多产出高分的写法？

## 2. 证据链

| 步骤 | 问题 | 结果 | 判定 |
|---|---|---|---|
| 组内供给（gate-v1，947 条 query × 8） | 样本之间有没有分数差 | 68% 的 query 有合格偏好对；8 选最好比 greedy 高 +8.5pp | 有差距 |
| 浅层探针 | 简单特征能否判好坏 | 只用长度 0.518；加词面 0.551；加 embedding 0.595 [0.544, 0.646] | 只有很弱的浅层信号 |
| 打分模型（1.7B + LoRA） | 模型能否学会判好坏 | 测试 0.464 [0.415, 0.513]；训练准确率升到 0.97，dev 不升 | **不可学** |
| 学习曲线 | 加数据有没有用 | 25% / 50% / 100% 训练 query：0.484 / 0.500 / 0.464 | 不随数据上升 |
| 只用分差 ≥ 0.2 的训练对 | 是不是小分差噪声淹没了信号 | 0.484 | 不是 |
| 事后超参检查 | 是不是打分模型没调好 | dev 选出 lr 2e-5（dev 0.614），测试 0.472 | 不是 |
| RM-BoN-8 | 用打分模型挑扩展有没有收益 | −0.8pp [−2.1, +0.4]；换成 lr 2e-5 的模型是 −0.4pp | **无收益** |
| GRPO 短跑（300 步） | 直接训练能否提升 | 评测 −0.16pp [−0.55, +0.23] | **未通过** |

## 3. 对比（plan 7.1）

3 个评测集共 1647 条 query（fiqa-test 648、scifact-test 300、android 699）。SFT 和 GRPO 都用 HF bf16 greedy 解码，同一流程生成、同一奖励服务打分。数值是数据集宏平均，置信区间来自按数据集分层的配对 bootstrap（10,000 次）。

| 指标 | SFT − 不扩展 | GRPO − SFT [95% CI] | fiqa | scifact | android |
|---|---|---|---|---|---|
| ΔM | +1.22pp | **−0.16pp** [−0.55, +0.23] | −0.44 | −0.14 | +0.09 |
| nDCG@10 | +1.16pp | −0.21pp [−0.72, +0.29] | −0.50 | −0.20 | +0.06 |
| R@30 | +1.35pp | −0.05pp [−0.55, +0.46] | −0.30 | 0.00 | +0.15 |

**评测分辨率**：置信区间半宽约 0.4pp。所以这次评测能排除"GRPO 带来 ≥ +0.25pp 的提升"，但测不出更小的效果。

**best-of-N 蒸馏没有做**（plan 第 5 步），所以原计划的三组对比只有两组。蒸馏是用真实检索分数挑样本再做 SFT，和 RM-BoN 不同：它挑的依据是答案，不是模型学到的规律。它能否超过 SFT，同样取决于"好样本有没有共同规律"。依据上面的证据链，预期也是持平，但这只是推断，没有实测。

**带 rerank 的线上路径没有测**（plan 7.2）。早先 G0 的结果是：在 rerank 路径上，扩展本身对 nDCG@10 只有 +0.004（不显著）。path A 上都没有提升，rerank 路径上大概率也测不出差别。

## 4. 训练过程

seed 42，300 步，每步 8 条 query × 8 个样本，lr 1e-5，beta 0.04，LoRA r=16，`scale_rewards="batch"`，平均每步约 39 秒。

| 步数 | 训练 ΔM | KL | 格式通过率 | 平均长度 |
|---|---|---|---|---|
| 1–50 | +0.008 | 0.0015 | 99.9% | 201 |
| 51–100 | +0.016 | 0.0018 | 99.9% | 204 |
| 101–150 | +0.011 | 0.0020 | 99.9% | 201 |
| 151–200 | +0.004 | 0.0020 | 99.8% | 201 |
| 201–250 | +0.019 | 0.0021 | 99.9% | 193 |
| 251–300 | +0.010 | 0.0021 | 99.8% | 200 |

- **训练奖励的线性斜率是每 100 步 +0.08pp，95% CI [−0.39, +0.58]**，和 0 没有区别。
- **训练奖励本身就是留出集指标**：300 步只用了 2400 条 query，结束时 epoch 0.51，每条 query 最多见过一次。所以每一步的奖励都是在**没训练过的 query** 上采样得到的。如果模型学到了能泛化的规律，这条曲线应该先升起来，但它没有。
- **训练是稳定的**：格式、长度、KL 都正常，没有 reward hacking，也没有崩溃。
- `frac_reward_zero_std` 全程为 0。这不是数据问题：`scale_rewards="batch"` 时 TRL 用的是整个 batch 的标准差，这个指标在该配置下没有意义。

## 5. 归因（plan 7.3）：是数据、算法还是模型

本节数字由 `attribution.py` 从已归档的产物复算（A–E 对应脚本输出的分节）。

| 假设 | 判断 | 关键证据 | 没排除的部分 |
|---|---|---|---|
| **数据 / 奖励信号** | **主因** | 只改几个词的扩展，分数平均也差 1.8pp（§5.1）；可学信号最多约 0.5pp（§5.2）；组内差异只占奖励总方差的 6%（§5.3） | 训练集 CQADup 中间类的标注质量没验证 |
| **算法（GRPO）** | 机制正常，不是主因 | 策略确实变了，训练稳定，梯度和组内方差都在；但在没见过的 query 上奖励不涨（§5.4） | 学习率偏低、只有 1 个 seed；没做"固定少量 query 能否把奖励推上去"的检验 |
| **模型（1.7B）** | 容量不是瓶颈 | 打分模型能记住训练对（0.97），但在新 query 上不如 10 个特征的线性探针；学习曲线平（§5.5） | 更强的模型确实写得更好（老师 R@30 +2.4pp），但这条路是蒸馏，不是 RL |

### 5.1 奖励对文本的微小变化很敏感（数据，B）

在评测集上，把 SFT 和 GRPO 的 greedy 输出按词的 Jaccard 重合度分组：

| 两份输出的重合度 | query 数 | 平均 ΔM | 平均 \|ΔM\| | \|ΔM\| ≥ 5pp 的比例 |
|---|---|---|---|---|
| 完全相同 | 78 | 0 | 0 | 0% |
| ≥ 0.9（只差几个词） | 133 | −0.19pp | **1.82pp** | 11% |
| 0.7–0.9 | 228 | +0.64pp | 2.60pp | 14% |
| 0.5–0.7 | 543 | −0.35pp | 3.68pp | 22% |
| < 0.5 | 665 | −0.29pp | 4.82pp | 28% |

gate-v1 组内也是同样的规律：8 个样本两两比较，重合度 0.2–0.3 的样本对平均差 7.03pp，0.5–0.6 的差 5.50pp，文本越接近分数差也只小一点。

- **只改几个词，分数平均就变 1.8pp**，11% 的 query 变化超过 5pp；各组的平均值都接近 0，变化只是在 query 之间来回抵消。
- **原因**：nDCG@10 和 R@30 是阶梯函数，一篇相关文档从第 11 名挤到第 10 名，分数就跳一下；扩展里多一个词，就足以改变某篇文档的排名。
- **对 GRPO 的含义**：奖励更像"这条 query 下的摸彩"，而不是"写法好坏"的平滑函数。组内分出的高低，大部分不对应可迁移的写法差异。

逐条 query 看 GRPO 和 SFT（D）：GRPO 更好的 16.8%，更差的 15.5%，持平的 67.7%；差距 ≥ 0.1 的，更好 105 条、更差 118 条。每条 query 平均绝对差 3.67pp，宏平均却只有 −0.16pp。GRPO 改变的是"哪些 query 赢、哪些输"，不是整体水平，这正是噪声的形状。

### 5.2 能学到的信号上限约 0.5pp（数据，A）

在新 query 上唯一被证明有效的信号是浅层探针（+embedding，准确率 0.595）。用它从 8 个样本里挑一个，在 gate-v1 测试集上（数据集宏平均）：

| 挑选方式 | 相对 greedy [95% CI] |
|---|---|
| 随机挑一个样本 | −0.66pp [−1.67, +0.32] |
| **探针挑** | −0.21pp [−1.60, +1.18] |
| 看答案挑最好的（oracle） | +8.53pp [+7.02, +10.04] |

- 探针比随机挑只多 **0.45pp** [−0.54, +1.42]，这就是目前能证明"可学"的全部空间，而且置信区间包含 0。
- 它连"采样比 greedy 差 0.66pp"的代价都补不回来。
- oracle 的 +8.5pp 是看着答案挑的，本质上就是 §5.1 的摸彩：只看结果挑最大值，纯噪声也会得到这个形状，不能当作可学空间。

GRPO 的停止判据是 +1pp，评测分辨率约 ±0.4pp。即使把这约 0.5pp 全部学到，也很难测出来，更过不了判据。

### 5.3 扩展的写法对分数的影响本来就小（数据，C）

把 gate-v1 每个样本的奖励方差拆开：不同 query 之间占 **93.8%**（query 本身难不难），同一 query 的 8 个样本之间只占 **6.2%**。GRPO 用组内均值做基线，只能利用这 6.2%，而其中大部分又是 §5.1 的噪声。从另一个角度看，SFT 相对不扩展的总提升也只有 +1.22pp，扩展这一环对检索的影响本来就有限。

**这不是"脏数据"的问题。** 天花板 query 和 R@30=0 的 query 已从训练池去掉；只用分差 ≥ 0.2 的偏好对，打分模型仍是随机水平（0.484）。标注噪声有一部分作用：并行会话的实验 E 显示，qrels 奖励和 LLM 评审的一致率按分差加权是 76%，分差 < 0.2 时只有 53%，≥ 0.4 时 94%。但主要矛盾是"写法 → 检索分数"这个映射对模型不可预测。

**奖励权重也放在了噪声更大的部分。** M 有 70% 的权重在 nDCG@10，而门槛数据里只看 R@30 时有偏好对的 query 只有 21%，R@30 口径的探针也都在 0.50–0.54。老师相对学生的真实优势主要在 R@30（§5.5），这部分在组内几乎看不到。

**数据配比不是原因。** 打分模型在 4 个训练数据集上都是随机水平：fiqa 0.48、programmers 0.46–0.51、scifact 0.44–0.53、unix 0.42–0.43，没有哪个数据集值得加权。评测上 android +0.09pp、fiqa −0.44pp，都在噪声范围内。

### 5.4 算法：机制正常，但有一个结构性局限（E）

`trainer_state.json` 每步的指标，前 50 步 → 后 50 步：

| 指标 | 前 50 步 | 后 50 步 | 解读 |
|---|---|---|---|
| 训练 ΔM | +0.0076 | +0.0103 | 不涨 |
| 组内奖励标准差 `reward_std` | 0.126 | 0.144 | 每步都有梯度可用 |
| KL（每 token） | 0.0015 | 0.0021 | 策略在动，按平均 200 token 算整条序列约 0.43 nats |
| 熵 | 0.776 | 0.774 | 没有熵崩塌，探索没丢 |
| 梯度范数 | 0.018 | 0.018 | 稳定，无尖峰 |
| 裁剪比例 | 0 | 0 | 每批样本只更新一次，新旧策略概率比恒为 1，裁剪不触发 |
| 平均长度 / 格式通过率 | 201 / 99.9% | 200 / 99.8% | 没有长度 hacking，格式没退化 |

- **策略确实变了**：95.3% 的 greedy 输出和 SFT 不同。GRPO 按设计把奖励差异转成了参数更新，只是这些更新在新 query 上不带来提升。
- **训练奖励本身就是留出集指标**（§4）：斜率每 100 步 +0.08pp [−0.39, +0.58]。如果是训练强度不够，应该看到缓慢上升，而不是平的。
- **旁证**：打分模型不涉及 RL 的任何不稳定因素，专门训练来判好坏，同样学不到。
- **结构性局限**：on-policy RL 只能放大策略自己已经产生的差异。T=0.7 下 8 个样本的差别主要是换个说法（§5.1），如果"写得更好"的样本很少出现在采样里，GRPO 就找不到它。
- **没排除**：lr 1e-5、300 步、1 个 seed 偏保守；也没做"固定少量 query 反复训练，看奖励能否推上去"的检验（§7）。

**浅层方向确实被用上了，但没有收益。** GRPO 的输出往"保留 query 关键词"的方向轻微移动，这正是 gate-v1 里好样本略占优的方向（vec 关键词保留率，好样本比差样本高 +0.018）：

| 特征（评测集均值） | SFT | GRPO |
|---|---|---|
| hyde 对 query 关键词的保留率 | 0.763 | 0.775 |
| vec 对 query 关键词的保留率 | 0.694 | 0.704 |
| hyde 词数 | 112.4 | 112.1 |
| 两条 vec 的词面重合 | 0.188 | 0.191 |

关键词保留率涨了约 1pp，检索效果没变：浅层信号要么太弱，要么不是因果性的。按 DPO spec 的决策矩阵，信号只在浅层时应改 prompt 或规则，但这里连浅层方向的移动都没有收益，改 prompt 的预期也很小。

### 5.5 模型：容量不是瓶颈，但更强的模型写得更好

- **不是容量问题。** 1.7B 打分模型在训练对上能到 0.97，说明它能区分训练集里的好坏，只是记住了这 1470 对；在新 query 上（0.46–0.47）还不如 10 个特征的线性探针（0.595）。数据少、模型大，问题是过拟合，换更大的模型只会更严重。学习曲线 25% / 50% / 100% = 0.484 / 0.500 / 0.464，加数据也没用。
- **但模型强弱确实有影响。** 2026-11-09 的另一组实验（SFT 为 Q8 量化版，检索口径和本文不同）里，老师模型（DeepSeek）的扩展比学生高 nDCG@10 +0.86pp、R@30 **+2.4pp**，都显著。"写得更好的扩展"真实存在，提升空间不是零。
- **这个差距不在学生的采样分布里。** 老师的优势是系统性的，GRPO 从 8 个自采样里只能找到换个说法的噪声。这正是蒸馏擅长、on-policy RL 不擅长的情况。

### 5.6 小结

1. **数据 / 奖励是主因**：在学生自己的采样里，好坏几乎由检索的偶然因素决定，能学的信号最多约 0.5pp。
2. **算法机制没问题**，但它的工作方式（只放大自采样里的差异）在这里正好够不到真实的提升空间。
3. **模型容量不是瓶颈**；老师和学生之间的差距说明下一步应该是蒸馏，而不是 RL。

## 6. RL 相比过滤式 SFT 多带来了什么

在这个任务上，什么都没带来。更准确地说：

- **两类方法都依赖同一个前提**：组内的好坏有可泛化的规律。可学性门槛直接测了这个前提，结果是否定的。
- **RL 多出来的两样东西，这里都用不上**：一是 on-policy 探索，但探索出来的差异是换个说法的噪声（§5.1）；二是按奖励大小加权，但分差大的偏好对也学不到（§2）。
- **剩下的提升空间在别处**。已有记录里能确认是真实的：老师模型和 SFT 之间的蒸馏差距（R@30 +2.4pp，显著），以及 router（扩展/不扩展）带来的延迟收益。

## 7. 局限

- GRPO 只跑了 1 个 seed、1 组超参（lr 1e-5、beta 0.04、300 步）。
- 只测了 path A，带 rerank 的线上路径没测。
- best-of-N 蒸馏没做，"三组对比"缺一组。
- 打分模型的超参检查是看过测试结果后补做的，不算预注册结果。
- 评测分辨率约 ±0.4pp，小于 0.25pp 的效果测不出来。

如果要把剩下的不确定性也排除，按价值排序：

| 实验 | 回答什么 | 成本 |
|---|---|---|
| **固定 32 条训练 query，GRPO 跑 100 步以上**（每条见很多次） | 算法能不能在见过的 query 上把奖励推上去。能推上去，说明算法没问题、是信号不能泛化；推不上去，说明是算法或超参的问题 | 约 1 小时 GPU |
| **老师方向检验**：对 gate-v1 的 query 生成老师扩展，看老师是否稳定优于学生的 8 个样本，以及组内越接近老师的样本是否分数越高 | 真实的提升空间是否在学生的采样分布之外；如果是，可把老师样本混进 GRPO 的组里，或直接做蒸馏 | 一批 DeepSeek API 调用，不需要 GPU |
| lr 5e-5，2 个 seed | 训练强度是否不足 | 约 7 小时 GPU，预期价值低 |
