FTS 统计隔离实验报告

问题：BM25 只用被查询 collection 的统计打分（方案 A：每个数据集一个独立 index），检索质量会不会变差？

结论：非劣效，通过

把 BM25 统计限定在目标 collection 内，端到端检索质量没有可测量的变化，按预先确定的规则判定为非劣效。同时，限定范围的 FTS 查询快了 4 到 25 倍。

  • 主终点（hybrid + rerank，q8 扩展，三个数据集宏平均）：nDCG@10 变化 +0.0000，95% CI [−0.0004, +0.0004]；R@30 变化 −0.0001，CI [−0.0003, +0.0000]。两个下界都远高于阈值（−0.005 / −0.01）。
  • 所有有效性检查都通过：向量结果逐个 query 完全一致，BM25 分数和新建的 FTS 表完全一致，index 指纹和封存的 G0 manifest 一致。
  • 效果这么小，主要因为 qmd 的 FTS 查询把所有词用 AND 连接，51% 到 94% 的自然语言原始 query 根本匹配不到文档。统计只影响少数有匹配的 query 的排序，而这些变化又被 RRF 名次融合和 reranker 进一步冲淡。

1. 背景

documents_fts 是所有 collection 共用的一张 FTS5 表。查询结果按 collection 精确过滤，但 BM25 的 IDF 和 avgdl 按整张表计算。我们希望改成「查询范围就是语料」：一个 collection 的检索结果只取决于它自己。上线前需要先确认，检索质量不会因此变差。

评测用的 G0 index 有 11 个 collection、256,673 篇文档，全部在一张 FTS 表里。其中 fiqa-dev 和 fiqa-test 指向同一份语料（57,638 个 hash 全部重合），scifact-train 和 scifact-v1 重合 5,164/5,183。也就是说，过去的评测中 FiQA 和 SciFact 的领域词 DF 都被翻倍了。

2. 方法

构造 index：复制后删除，不重新 embed

先把 G0 index 复制 6 份，再对副本执行 qmd collection remove 删掉不需要的 collection。删除只影响被删 collection 的 documents、FTS 行和向量分区，目标 collection 的数据不变。所以不需要重新 embed，两种 index 唯一的区别就是 FTS 表里还有哪些文档。

G0 index 实际上还是旧的向量存储格式（vectors_vec），每个副本第一次打开时会自动迁移到按 collection 分区的格式，约需 1 分钟。之后所有副本（包括 S）都执行了同样的 qmd cleanup，清空了 G0 遗留的 1,034 条 LLM 缓存，避免只有 S 能命中旧的 rerank 缓存。

哪些文档能匹配上和统计无关，所以 S、D、I 三种 index 下为空的 query 完全相同，统计只影响有匹配的 query 的排序。作为参考，BEIR 的 BM25（OR 语义）在 FiQA 上的 nDCG@10 约为 0.24。在 hybrid 流程里，BM25 主要通过 lex: 扩展（短关键词）起作用。

  • 重复语料几乎没有影响。重复一份语料会让所有领域词的 DF 一起翻倍，IDF 整体平移，同时包含这些词的文档之间相对顺序基本不变。
  • BM25 单路下，隔离反而让 Android 略差（nDCG@10 −0.0042）。一个可能的解释是：只用 Android 的 2.3 万篇文档时，IDF 的估计不如在 25.7 万篇（包括另外三个 CQADupStack 子论坛）上稳定。这个解释没有验证，而且这个差异在 hybrid q8 中完全消失（−0.0000）。
  • FiQA 和 Android 约有 12.5% 的 query 的 BM25 top-10 发生变化；到 hybrid q8 阶段，这个比例降到约 4.9%。

在共享 index 上，限定 collection 的查询要先物化所有 collection 的全部匹配，再做过滤；collection 越小，这部分浪费越大。hybrid 每个 query 要执行好几次 FTS（原始 query 加上 lex 扩展），所以端到端 p50 快了 0.3 到 0.45 秒（5% 到 10%）。这些延迟数据来自同一台机器的单次运行，只能作为方向参考。

8. 为什么影响这么小

  1. AND 语义：大多数原始 query 根本没有 FTS 结果，统计没有机会影响它们。
  2. 统计只改变排序，不改变匹配集合：哪些文档能被召回完全不受影响，变化的只是同时包含所有查询词的文档之间怎么排。
  3. 只用名次的融合：FTS 列表进入 RRF 时只用名次，最终排序又由「RRF 名次 + rerank 名次」融合决定，BM25 名次的局部变化被向量列表和 reranker 冲淡。
  4. 重复语料只造成整体平移：DF 翻倍对同一 query 下所有文档的影响方向一致，相对顺序几乎不变。

9. 建议

  1. 可以采纳「collection 内统计」这个原则。质量非劣效已经得到证实，同时还有两项实际收益：结果可复现（一个 collection 的排序不再受 index 里其他 collection 影响），以及限定范围的查询快 4 到 25 倍。
  2. 不要期待质量提升。改动的理由是语义清晰、可复现和延迟，不是 nDCG。
  3. 实现时还需要单独验证的两个场景（本实验没有覆盖）：
    • 小 collection：本实验最小的 collection 有 5,183 篇。几十到几百篇时，IDF 截断的影响需要另外测，可以从 SciFact 中抽样出小语料来做。
    • 多 collection 查询：本实验每个 query 都只查一个 collection。方案 C 下跨表按分数合并的效果，需要另外评测。
  4. Strong-signal 阈值保持不变，隔离后触发率基本相同。
  5. 以后的评测 index 应该去掉重复语料，或者每个数据集单独建 index。这次测出来的影响可以忽略，但这样做能消除一个不必要的干扰因素。
  6. 值得单独研究的现象：AND 语义让 51% 到 94% 的原始 query 在 FTS 中没有任何结果。原始 query 的 FTS 列表目前对大多数 query 没有贡献。是否需要在 AND 没有结果时退回到 OR，可以作为一个独立课题，用同一套评测来验证。

10. 局限

  • 只测了 3 个英文数据集（FiQA、SciFact、CQADupStack Android），collection 都有几千篇以上文档，没有测试 CJK 语料。
  • 非劣效阈值是根据之前 SFT 效应的量级主观确定的。实际 CI 比阈值窄得多，阈值的具体取值不影响结论。
  • bench 结果中 qmd_dirty 为 true，是因为分支上有新增的实验脚本，src/ 没有任何改动（commit 2ad5c78）。
  • 延迟是单机单次测量，没有做重复实验。
